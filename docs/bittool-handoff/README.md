## Things to watch

The current wallet QR is protocol version 1. It exports **four Bitcoin account xpubs**
(`p2wpkh`, `p2tr`, `p2sh-p2wpkh`, `p2pkh`), an **EVM** account xpub, a **TRON** account xpub, and
**three Solana addresses** (standard, trust, legacy). Ed25519 derivation is hardened, so a
watch-only wallet cannot derive one Solana address from another — all three have to be sent.
**Read each entry by its `chain` and `script` or `profile` field, never by array index.**

`mode: "full"` is an existing wire field and should not become a UI mode choice. Differences
between the reference document, older implementations and the current code are recorded in the
prompt.

Each string in `frames` should be encoded as its own QR code and cycled. Do not encode the whole
array, or the JSON file, as a single QR code. **All frames must be collected before decoding.**
A BC-UR string and its CBOR hex are two representations of the same content.

In the signing vectors, `expected.serializedTransaction` is `0x`-prefixed hex for EVM and base64
for Solana; Bitcoin's `signedPSBTBase64` is a PSBT. These fields exist so the hot side can
compare its assembled result. A real signature QR usually returns only the signature, and a PSBT
for Bitcoin. A production implementation must verify signatures independently and must not
substitute a fixed `expected` string for verification.

These vectors come from public BIP39 test accounts. Every transaction is for testing, with
synthetic UTXOs, blockhashes and reference blocks. **Nothing is broadcast and nothing holds
assets.** No real wallet phrase or password is needed.

## Regenerating

Requires the BitTool Signer engine with its dependencies installed, and Node 20.19.0 or later.
From this directory:

```sh
node generate-fixtures.mjs /absolute/path/to/BitToolSigner/engine
```

Run the protocol regressions in the BitTool Signer engine directory:

```sh
node --test test/wallet-pairing.test.mjs test/protocols.test.js
```

The script checks that the source did not change between before and after generation, and that
`signer.js`'s actual digest matches the bundle manifest. After generating a new snapshot, a
developer still has to re-check the protocol facts in the prompt: the script does not update the
rules, the acceptance record or the test results written in Markdown.
